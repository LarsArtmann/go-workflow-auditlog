## e) WHAT WE SHOULD IMPROVE 🎯

### Process improvements (this session)

1. **Check signing conventions before tagging.** Query `git tag -v` on the
   prior tag as a mandatory pre-tag step. Sign (or explicitly decide not to)
   *before* creating the tag.
2. **Always run the snapshot release, not just `goreleaser check`.** Config
   validation ≠ release validation. `goreleaser release --snapshot --clean`
   must be a release gate.
3. **Read docs you link to.** I pointed the CHANGELOG at MIGRATION.md without
   verifying it was complete for v0.8.0's scope. Link-target verification is
   now a checklist item.
4. **Pre-commit hygiene over daemon reliance.** The auto-commit daemon
   produced generic commit messages and lumped unrelated changes. For releases,
   stage a single intentional `release: v0.8.0` commit before the tag.

### Release-process improvements (durable)

5. **Add a tag-triggered release workflow** to `.github/workflows/` so pushing
   `v*` tags runs goreleaser automatically (no manual local run, no forgotten
   `GOEXPERIMENT`). Currently releases are entirely manual and easy to flub.
6. **Add govulncheck + coverage gate for viz AND live** to CI, not just core.
   Currently only core has a coverage gate (≥92%) and vulncheck; viz has
   vulncheck but no coverage floor; live has neither vulncheck (deferred on
   GO-2026-5856) nor a coverage floor.
7. **Add Keep-a-Changelog compare-link footer** to CHANGELOG.md for clickable
   version diffs on GitHub/website.
8. **MIGRATION.md should be release-checked.** Add "verify migration doc covers
   all shipped modules" to the release checklist.
9. **STABILITY.md version table.** Consider a "what changed in each version"
   stability delta so consumers can see at a glance what's newly-stable vs
   newly-evolving per release.
