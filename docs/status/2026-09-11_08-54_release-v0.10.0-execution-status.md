2. **`checkout --detach HEAD` in a linked worktree is a no-op** — `HEAD` there resolves to the worktree's own old detached commit, not the main repo's HEAD. I ran an entire verification suite against a **stale tree** and initially misread its (legitimate) findings as fresh regressions. Cost: one full test cycle. The correct call is `checkout --detach <explicit-sha>`.

I re-applied it AND made the test whitespace-insensitive so the next clobber can't break the gate — but the underlying coordination problem is yours to adjudicate (question 2 below).
