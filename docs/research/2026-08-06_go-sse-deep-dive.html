00Summary

go-workflow-auditlog's live module depends on github.com/larsartmann/go-sse for exactly three symbols: sse.ContentType (a string constant), sse.WriteEvent (the wire-format writer), and sse.Event (the struct literal). Every higher-level capability the library offers — the generic Broadcaster[T] fan-out, the Stream connection manager, the Replay/EventStore reconnection mechanism, graceful Shutdown, Health() reporting — is reimplemented by hand in live/hub.go and live/server.go. The three symbols that are used are used correctly.

The bottom line The project imported go-sse for its wire-format primitives but rebuilt the entire layer above them. Approximately 195 lines of hand-rolled SSE plumbing in hub.go and server.go duplicate functionality that go-sse already provides, tests, benchmarks, and race-tests. The most consequential gap is the absence of reconnection replay: a dashboard client that briefly loses its SSE connection misses all events during the outage, receiving only a heavier full-state snapshot on reconnect.

◆Current usage baseline

The live module's SSE architecture is a hand-rolled three-layer stack. Each layer reimplements something go-sse ships out of the box:

+

01Findings — capability by capability

Missed Opportunity · Critical impact

Hand-rolled Hub reimplements Broadcaster[T] entirely

live/hub.go:1-141 (entire file) · reimplements sse.Broadcaster from fanout.go

go-sse ships Broadcaster[T] — a generic, thread-safe, race-tested subscriber hub with non-blocking broadcast (drop-on-full), Subscribe/ Unsubscribe via channel pointer identity, BroadcastMany (batch fan-out in a single lock pass), SubscriberCount, OnSubscribe/ OnUnsubscribe hooks, configurable buffer size (WithBufferSize), graceful Shutdown(ctx), instant Close(), and structured Health(). Available since v0.1.0; lifecycle features added in v0.4.0.

The project's Hub (live/hub.go) reimplements the core of this: a map[uint64]*Subscriber, non-blocking broadcast() with a select/default drop pattern, Subscribe/Unsubscribe, and ClientCount. What it doesn't have that Broadcaster does: graceful shutdown, structured health, lifecycle hooks, batch broadcast, configurable buffer, and O(1) unsubscribe via channel pointer (the Hub uses a map lookup by ID instead).

Recommendation Replace Hub with sse.Broadcaster[jsontext.Value]. The Hub broadcasts pre-marshaled jsontext.Value (not sse.Event), but Broadcaster is generic — Broadcaster[jsontext.Value] works directly. The domain-specific SignalComplete lifecycle (closing a done channel) can remain as a thin wrapper around the broadcaster or as a separate completion signal.
Before (hub.go, 141 lines)
After (using Broadcaster)
// Hand-rolled Hub — 141 lines
type Hub struct {
    mu       sync.RWMutex
    clients  map[uint64]*Subscriber
    nextID   uint64
    complete bool
}

func (h *Hub) broadcast(data jsontext.Value) {
    h.mu.RLock()
    defer h.mu.RUnlock()
    for _, sub := range h.clients {
        select {
        case sub.ch <- data:
        default:
        }
    }
}
// Using go-sse Broadcaster — ~10 lines
type Hub struct {
    bcaster  *sse.Broadcaster[jsontext.Value]
    complete atomic.Bool // SignalComplete
}

func NewHub() *Hub {
    return &Hub{
        bcaster: sse.NewBroadcaster[
            jsontext.Value](
            sse.WithBufferSize[
                jsontext.Value](128),
        ),
    }
}

func (h *Hub) broadcast(data jsontext.Value) {
    h.bcaster.Broadcast(data)
}
Missed Opportunity · Critical impact

Hand-rolled SSE handler reimplements Stream

live/server.go:426-479 (handleSSE) · reimplements sse.Stream from stream.go

go-sse's Stream manages a single SSE connection: NewStream(w, r) sets SSE headers and writes 200 OK, Send(Event) writes + flushes with mutex-guarded concurrent safety, Heartbeat(ctx, interval) runs a keep-alive goroutine, Context() exposes request cancellation, Close() satisfies io.Closer, and LastEventID() reads the reconnection header. Race-tested for Send+Heartbeat+Close concurrent safety.

The project's handleSSE reimplements all of this manually: a flusher type-assertion, manual header setup, a hand-rolled heartbeat ticker, and a select loop that calls sse.WriteEvent + flusher.Flush() on each event. This is ~54 lines of plumbing that Stream handles in ~5 lines of handler code.

Recommendation Use sse.NewStream(w, r) for header setup and status, then stream.Send(evt) for each event. The project's extra headers (X-Accel-Buffering: no, no-transform) can be added after SetHeaders or before NewStream. The heartbeat becomes go stream.Heartbeat(ctx, interval) — one line replacing the entire ticker case.
Before (server.go:426-479)
After (using Stream)
// 54 lines of manual plumbing
func (srv *Server) handleSSE(
    w http.ResponseWriter,
    r *http.Request,
) {
    flusher, ok := w.(http.Flusher)
    if !ok { ... return }

    w.Header().Set("Content-Type", sse.ContentType)
    w.Header().Set("Cache-Control", "no-cache, no-transform")
    w.Header().Set("Connection", "keep-alive")
    w.Header().Set("X-Accel-Buffering", "no")

    sub := srv.hub.Subscribe()
    defer srv.hub.Unsubscribe(sub.id)

    srv.sendSnapshot(w, flusher)

    heartbeat := time.NewTicker(...)
    defer heartbeat.Stop()

    for {
        select {
        case <-r.Context().Done(): return
        case <-sub.done:
            srv.sendComplete(w, flusher)
            return
        case evt := <-sub.ch:
            sse.WriteEvent(w, sse.Event{...})
            flusher.Flush()
        case <-heartbeat.C:
            w.Write([]byte(": heartbeat\n\n"))
            flusher.Flush()
        }
    }
}
// ~15 lines using Stream
func (srv *Server) handleSSE(
    w http.ResponseWriter,
    r *http.Request,
) {
    stream := sse.NewStream(w, r)
    defer func() { _ = stream.Close() }()

    // Project-specific extra headers
    w.Header().Add("Cache-Control", "no-transform")
    w.Header().Set("X-Accel-Buffering", "no")

    go stream.Heartbeat(
        stream.Context(), srv.config.HeartbeatInterval)

    sub := srv.hub.Subscribe()
    defer srv.hub.Unsubscribe(sub.id)

    srv.sendSnapshot(stream)

    for {
        select {
        case <-stream.Context().Done(): return
        case <-sub.done:
            srv.sendComplete(stream)
            return
        case evt := <-sub.ch:
            stream.Send(sse.Event{
                Event: "event",
                Data: string(evt),
            })
        }
    }
}
Missed Opportunity · Medium impact

Heartbeat frame hardcoded instead of WriteHeartbeat

live/server.go:471 · w.Write([]byte(": heartbeat\n\n"))

go-sse exports WriteHeartbeat(w) which writes the exact same SSE comment frame (: heartbeat\n\n) from a shared heartbeatFrame constant. More importantly, Stream.Heartbeat(ctx, interval) runs the entire heartbeat goroutine (ticker + context cancellation + mutex-guarded write + flush) in one call.

The project duplicates the frame bytes as a string literal ([]byte(": heartbeat\n\n")) and the entire ticker loop inline in the handleSSE select statement. This is a line-for-line duplicate of go-sse's implementation.

Recommendation If adopting Stream (finding #2), the heartbeat case disappears entirely — go stream.Heartbeat(ctx, interval) replaces it. If keeping the manual handler, at minimum replace the hardcoded bytes with sse.WriteHeartbeat(w).
Missed Opportunity · High impact

No reconnection replay — disconnected clients miss events

Not implemented anywhere · go-sse Replay/EventStore/LastEventID all unused

go-sse provides a complete reconnection replay mechanism: EventID (branded type with validation), Stream.LastEventID() / LastEventIDFromRequest(r) to read the browser's reconnection header, EventStore interface for storing/retrieving events by ID, and Replay(stream, store, lastID) / ReplayFiltered(stream, store, lastID, pred) to send missed events on reconnect. The browser's EventSource sends Last-Event-ID automatically on reconnection.

The project has no reconnection support at all. When a dashboard client's SSE connection drops (network blip, proxy timeout, tab sleep) and reconnects, it receives the current full-state snapshot — not the specific events it missed during the outage. For a real-time monitoring dashboard where individual events carry per-step status changes, this means the client may miss critical intermediate states. The snapshot is a fallback (it contains the full report), but it's heavier, doesn't preserve event-ordering continuity, and requires re-rendering the entire dashboard state instead of incrementally applying missed events.

Recommendation Implement an EventStore backed by the auditor's in-memory event slice (already tracked by Recorder.events). Assign EventIDs to broadcast events. On SSE handler entry, check stream.LastEventID() and call sse.Replay(stream, store, lastID) before entering the event loop. The auditlog already stores events by sequence number — mapping sequence to EventID is straightforward.
Missed Opportunity · Medium impact

No graceful SSE subscriber drain on server shutdown

live/server.go:281-296 (Shutdown) · calls http.Server.Shutdown but not hub drain

go-sse's Broadcaster.Shutdown(ctx) (v0.4.0) stops accepting new subscribers, waits for every active subscriber's buffer to drain (consumers catch up), then closes all channels. Returns ctx.Err() if the deadline fires before the drain completes; the caller can retry or fall back to Close().

The project's Server.Shutdown(ctx) calls http.Server.Shutdown(ctx) which waits for active HTTP connections to finish — but SSE connections are long-lived by design. In-flight events sitting in subscriber buffers (up to 128 per subscriber) may be lost when the HTTP server forces connections closed. There is no mechanism to drain the event buffers before shutting down.

Recommendation If adopting Broadcaster (finding #1), call broadcaster.Shutdown(ctx) before or alongside httpServer.Shutdown(ctx) in Server.Shutdown. This ensures buffered events are delivered to connected clients before the connections are torn down.
Missed Opportunity · Low-medium impact

Custom health endpoint misses Broadcaster.Health()

live/server.go:391-424 (handleHealth) · constructs healthResponse manually

go-sse's Broadcaster.Health() returns a BroadcasterHealth struct with Closed, Draining, SubscriberCount, and BufferSize — a structured snapshot safe to call from any goroutine, designed for k8s liveness/readiness probes.

The project's handleHealth manually constructs a healthResponse with Clients (from hub.ClientCount()), Events, and Dropped. It doesn't report lifecycle state (draining/closed) because the Hub doesn't track it. If Broadcaster were adopted, Health() would provide this for free.

Recommendation If adopting Broadcaster, wire broadcaster.Health() into the health response. The existing Events/Dropped fields (from the auditor) complement the broadcaster's lifecycle state.

WriteEvent + ContentType + Event — the 3 used symbols

live/server.go:434,463,491,511 · 4 call sites total

The three symbols that are imported are used correctly: sse.ContentType for the Content-Type header (not a magic string), sse.WriteEvent(w, evt) for SSE wire-format serialization (with multi-line data splitting), and sse.Event{Event: "...", Data: "..."} as struct literals. No misuse, no anti-patterns. The wire format is right.

The issue is not that these are wrong — it's that only these are used, when the library offers an entire connection-management and fan-out layer above them.

04Conclusion

go-workflow-auditlog uses go-sse as a wire-format constant library, not as the SSE infrastructure framework it is. The three imported symbols (ContentType, WriteEvent, Event) are used correctly, but ~195 lines of hand-rolled code in hub.go and server.go duplicate the Broadcaster, Stream, heartbeat, and header management that go-sse already provides — tested, race-tested, and benchmarked at scales up to 10,000 subscribers.

The single highest-leverage action is replacing the hand-rolled Hub with sse.Broadcaster[jsontext.Value] (opportunity #1, priority 15). This eliminates the most duplication and unlocks Shutdown, Health, and configurable buffer size for free. The second highest-leverage action is implementing reconnection replay (opportunity #7) — the only finding that affects user-visible behavior, not just code quality.

Adoption score: 28/100 (Surface-level) The library is present and the wire format is right, but the vast majority of go-sse's value — connection management, fan-out, reconnection, lifecycle — is reimplemented by hand. Upgrading from "imported for primitives" to "leveraged as infrastructure" would eliminate ~195 lines of duplicated code and add reconnection support that the dashboard currently lacks.
